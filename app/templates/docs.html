{{ settings.APP_NAME }} API

Create an order, send your customer to its checkout_url, and get a signed webhook when it is paid. Money goes straight to the gateway account or wallet you connected in the dashboard.

Base URL: {{ base }}/api/v1

  1. Connect a gateway or wallet in Integrations.
  2. Create a test key in Developers.
  3. Create an order with the request below and open its checkout_url.
  4. Add your webhook URL and verify the signature on your server.

Authentication

Send your secret key in the Authorization header. Test keys start with sk_test_ and live keys with sk_live_. Keep them on your server, never in browser or app code.

Authorization: Bearer sk_test_xxxxxxxxxxxxxxxx

GET/api/v1/ping returns your key's mode, which is a quick way to check a key works.

Create an order

POST/api/v1/orders

FieldTypeNotes
amountnumberRequired. In major units: 499.00 rupees or 10.5 USDT. INR allows 2 decimals, USDT 6. Minimum 1.
currencystringINR (default) uses your gateway. USDT uses your wallet.
descriptionstringShown on the payment page. Up to 250 characters.
referencestringYour own order or invoice number. It comes back in webhooks.
customer_email, customer_phonestringOptional, passed to the gateway.
return_urlstringThe customer is sent here after paying, with order_id and status added. Always confirm payment from the webhook or the API, not from this redirect.
metadataobjectUp to 20 text key/value pairs of your own.
expires_in_minutesinteger20 to 10080. Default 30. PhonePe orders last at most 60.
gatewaystringINR only: razorpay, cashfree or phonepe. Default is the first one you connected.
networkstringUSDT only: TRC20 or BEP20. Default is the first wallet you saved.

Send an Idempotency-Key header (any unique text, such as your order number) so a retried request returns the same order instead of creating a second one.

curl {{ base }}/api/v1/orders \
  -H "Authorization: Bearer sk_test_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: order-1001" \
  -d '{
    "amount": 499,
    "currency": "INR",
    "reference": "order-1001",
    "description": "Pro plan",
    "return_url": "https://yourstore.com/thanks"
  }'

status is one of created (waiting for payment), paid, expired, cancelled or failed. Ship the goods only when it is paid.

Retrieve, list, cancel

GET/api/v1/orders/{id} returns one order. We re-check it with the gateway first, so it is always current.

GET/api/v1/orders?limit=20&status=paid&starting_after=ord_... lists newest first. Returns data and has_more.

POST/api/v1/orders/{id}/cancel cancels an order that is still unpaid.

Keys only see orders of their own mode: test keys see test orders, live keys see live orders.

Webhooks

Set your URL in Developers. We send a POST with a JSON body for these events: order.paid, order.expired, order.cancelled and order.failed. Answer with any 2xx status. Otherwise we retry up to 8 times over about a day.

{
  "id": "evt_5c1e7a90b2d4f318",
  "type": "order.paid",
  "livemode": false,
  "created": "2026-01-15T10:34:12Z",
  "data": { "order": { "id": "ord_8f3a1c9d2b7e4a10", "status": "paid", "amount": "499.00", "currency": "INR" } }
}

Verify the signature

Each request has X-PayGate-Signature: t=1736937252,v1=<hex>. The value is an HMAC-SHA256 of {timestamp}.{raw body} using your signing secret from the dashboard. Compute it from the raw body, compare in constant time, and reject old timestamps. Handle each id only once, since retries can repeat an event.

import hmac, hashlib, time

def verify(raw_body: bytes, header: str, secret: str, tolerance: int = 300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    ts, sig = parts["t"], parts["v1"]
    if abs(time.time() - int(ts)) > tolerance:
        return False
    expected = hmac.new(secret.encode(), ts.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, sig)
const crypto = require("crypto");

// Use express.raw({ type: "application/json" }) so req.body is the raw Buffer
function verify(rawBody, header, secret, tolerance = 300) {
  const p = Object.fromEntries(header.split(",").map((s) => s.split("=")));
  if (Math.abs(Date.now() / 1000 - Number(p.t)) > tolerance) return false;
  const expected = crypto.createHmac("sha256", secret)
    .update(p.t + "." + rawBody.toString("utf8")).digest("hex");
  return expected.length === p.v1.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(p.v1));
}

Test mode

Orders made with a sk_test_ key never touch a gateway or the blockchain. Open the checkout_url and press Simulate successful payment. You get the same webhook and Telegram message as a real payment, with livemode: false.

To try a real gateway flow without real money, add your gateway's sandbox keys in Integrations and use a sk_live_ key. Live keys need an approved account.

USDT payments

A USDT order shows your wallet address and an exact amount. To tell payments apart we add a tiny unique amount (under 0.01 USDT) to each order, for example 10.004217. The customer must send exactly that amount on the chosen network. crypto.amount in the order object is the exact figure.

We confirm after the network's confirmations: TRON waits for a confirmed block, BNB Smart Chain waits 12 blocks. Payments that arrive within 30 minutes after expiry are still matched.

Errors and limits

Errors come as {"error": {"code": "...", "message": "..."}} with a matching HTTP status.

StatusCodeMeaning

403kyc_requiredLive payments need an approved account.
